The approved lessons establish the experience to preserve. Shared code fixes are applied once; every affected lesson still needs coverage evidence. Memory notes alone are not release gates.

## Work order

1. Complete discovery: assessment handoff→approved K showcase/sample; assessment result→existing individual journey→approved lesson by standard. Keep school grade separate from assessed skill level. Never force every child into K Unit1. Preserve existing free-sample, starter and paid access policy.
2. Refresh coverage across the complete K–1 author catalogue: identify the actual shared component and version used by every interaction. Backport shared player fixes to author and QA trees deliberately, preserving concurrent work. Record which lessons are affected by each patch.
3. Run machine checks across every relevant activity/state, including alternative difficulty branches, wrong answers, retries, unavailable audio and microphone, and summary states. Fix shared failures before individual content review. Apply picture rules by question purpose; blindly adding images can give answers away.
4. Visually inspect every changed/new image and flagged scene. Check anatomy, action, crop, same-character continuity and answer relevance. Transcription checks flag recordings for listening; they cannot independently certify phonemes or natural delivery.
5. For each unit, prepare a review packet containing only changed teaching, uncertain standards alignment, questionable media, and a small representative set of interactions. Founder/Jennifer review2–3 contrasting lessons in full when a new interaction or grade style is introduced; otherwise review deltas and exceptions. Testing must still cover all lessons, not just the sample.
6. Release one approved unit at a time with its own exam, persisted evidence and the existing journey handoff. Keep approvals tied to content/asset/runtime versions so later changes invalidate only affected checks. Never infer automatic grade promotion from a short unit check.

## Required quality layers

**Shared mechanics:** full-tile hit areas, whole-bin drop/tap, balanced choices, narration ownership, word highlights, mic cleanup, two-error support, feedback dwell/fade, final-match audio, state and carrot idempotency.

**Authored assets/data:** useful pictures at legible sizes, no malformed characters, coherent opening scene/ambience, clean voice, correct letter names and syllable beats, relevant response pictures, meaningful distractors and fresh transfer questions.

**Human instructional judgment:** explicit explanation, genuine skill practice, reasonable load, no answer clues that defeat the skill, and fun warmups. No automated system can honestly guarantee these from a screenshot or filename.

## Timing

Start by running one next K unit through the shared-check→exceptions→review→release loop. Measure actual exception rate and review time before promising a catalogue completion date. Asset corrections, speech listening and instructional exceptions determine the workload; authoring another template is not the bottleneck to optimize first.
