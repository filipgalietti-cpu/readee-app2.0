# Approved Kindergarten Unit 1 integration

Scope: founder-approved September 14, 2026. Eight approved experiences and the ten-question Story Garden exam. The separate authoring/QA tree remains untouched.

## Entry and progression

- `/learn/unit-one?child=<owned reader>`: explicit approved unit, completion checks, exam entry.
- `/learn/unit-one?child=<owned reader>&lesson=<approved slug>`: full-screen warm-up → approved lesson → adaptive practice → celebration.
- Existing `/learn?standard=…&child=…` links resolve to the approved experience when enabled. Other standards retain their existing engines.
- Journey displays the unit entry only when the server enables it. No new placement decisions, grade promotion, or reassignment of an older child's curriculum.
- Current signup-cohort, placement, grandfathered free allowance, trial and paid access rules are preserved at the page and API layers. Every API operation verifies parent ownership. The reviewed mixed-strand unit is not identical to the legacy domain-based free unit; changing that commercial policy is deliberately outside this integration. Story Garden opens after the eight packages have completed practice. Completion is distinct from mastery: a low score is stored honestly, without inflating it to the legacy journey's three-correct threshold.

## Persistence

New `approved_unit_sessions` records are scoped by child, release version and package. State lives in Supabase; the production player never writes preview localStorage. UI progression stays responsive with serialized saves. A visible retry notice and navigation guard protect unsaved work. Concurrent/stale writers receive 409. The transaction records practice results, spendable/lifetime carrots and last-lesson timestamp together, once per package release. Reopening a celebration does not award again.

The server validates the actual selected option, sorting placements, word order, matching pairs and highlighted positions against the authored package. Client `correct`, first-response summaries and carrot amounts do not decide the persisted score. The server checks the selected question sequence against its selector. First submitted answer histories cannot be erased on a later save. A signed, child/package/rubric-bound receipt supports objective spoken exam answers. Subjective reflections and browser pronunciation coverage remain practice evidence; client Azure confidence is not an independently authenticated acoustic measurement.

Exam uses the approved ten-question/core plan and existing 80% provisional readiness rule. Missing, assisted and unavailable responses remain distinct; they cannot establish readiness. Retake scheduling/fresh exam forms and automatic remedial reassignment are not introduced by this integration. Completed packages reopen their celebration/results. Production hides the preview’s reset button because resetting a persisted attempt would erase first-answer history. A future replay mode must preserve that history and award no duplicate completion bonus.

## Audio and privacy

Authenticated package-scoped Luna endpoints replace `/api/dev/*`. API keys remain on the server. Atomic per-parent hourly budgets: 30 speech token mints, 120 response checks. Tokens are cached for eight minutes in memory. A Speech token can still authorize arbitrary Azure streaming for its lifetime; mint limits do not cap streaming concurrency or total audio seconds. Production capacity must account for this existing Azure architecture.

Response text is bounded to 240 characters, transiently evaluated and not stored in the session database. Audio streams directly to Azure. No raw transcripts/audio are added to analytics or application logs by this integration. Child deletion cascades to package state; budget rows expire opportunistically after two days and cascade with the auth user.

## Local verification and limits

All fixtures use synthetic parents/children. The browser harness rejects external traffic and sends Supabase requests to a local adapter backed by an actual PostgreSQL engine (PGlite); the application API handlers and the migration run unmodified. This checks integration behavior, not the actual deployed project's grants, triggers or credentials. Live Azure microphone recognition still needs an authenticated staging smoke check.

The development browser run exposed empty/truncated JavaScript responses from the local Next webpack development server during repeated cold navigation. The harness can retry an empty development runtime, and strips conditional cache headers. These are test-only measures, not changes to production browser behavior. A production build and staging check remain the release standard.

Unit tests: `node_modules/.bin/vitest run tests/approved-unit tests/placement-read-grade.test.ts tests/placement-speech-timing.test.ts`.

Current production main has no factory teaching-sequence prebuild gate; no such gate or unfinished factory subsystem is imported.
